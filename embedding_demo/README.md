## 📖 核心概念

### 什么是 Embedding？

`Embedding` 组件是文本向量化的核心工具，它能将文本转换为高维向量表示，使得**语义相似的文本在向量空间中距离较近**。

```
传统匹配: "苹果" ≠ "水果"  ❌
Embedding:  "苹果" ≈ "水果"  ✅ (语义相似)
```

### 🎯 主要应用场景

- 🔍 **语义搜索**: 查找与用户查询意图最相符的文档
- 📊 **文本相似度计算**: 判断两段文本在意思上的接近程度  
- 🎯 **文本聚类分析**: 将相似的文本自动分组或分类
- 🤖 **RAG系统**: 为检索增强生成提供向量基础
- 💡 **推荐系统**: 基于内容相似度的智能推荐

## 🔧 核心API

### 基本接口

Embedding组件的核心接口非常简洁：

- **EmbedStrings**: 将字符串列表转换为向量列表
  - **输入**: `[]string` - 待向量化的文本列表
  - **输出**: `[][]float64` - 对应的向量表示
  - **选项**: 可选配置参数

## 💡 使用最佳实践

### 性能优化

1. **批量处理**: 尽量批量处理多个文本，减少网络开销
2. **合理批次大小**: 根据硬件能力调整批次大小（推荐10-50）
3. **结果缓存**: 对重复文本进行向量缓存

## 🚀 进阶用法

### 自定义相似度计算

项目提供多种相似度计算方法：

**余弦相似度**（最常用）:
- 计算两个向量夹角的余弦值
- 值范围：-1到1，越接近1越相似
- 适用于大多数语义相似度场景

**欧几里得距离**:
- 计算向量间的直线距离
- 距离越小表示越相似
- 适用于向量长度有意义的场景

**曼哈顿距离**:
- 计算各维度差值的绝对值之和
- 计算效率高，适合大规模数据

### 向量缓存机制

实现LRU缓存策略避免重复计算：

- 内存限制控制
- 最近最少使用策略
- 线程安全访问
- 自动清理机制

## 🤝 故障排查

### 常见问题

**Q: 向量化失败，提示API Key错误**
```
❌ 错误: invalid api key
✅ 解决: 检查ARK_API_KEY环境变量或config.yaml配置
```

**Q: 相似度计算结果异常**
```
❌ 错误: 向量维度不匹配
✅ 解决: 确保所有向量来源于同一个模型
```

**Q: 批量处理速度慢**
```
💡 优化: 调整批次大小，避免单个文本过长
```

1. **开启详细日志**: 设置日志级别为DEBUG
