# Eino 回调机制详细指南

## 📖 **文档概述**

本文档基于 Eino 官方文档 `https://www.cloudwego.io/zh/docs/eino/core_modules/chain_and_graph_orchestration/callback_manual/` 的内容进行详细总结，涵盖了回调机制的核心概念、使用方法、代码示例和最佳实践。

## 🎯 **回调机制核心概念**

### **设计目的**
Eino 的回调机制主要解决以下两个核心问题：

1. **横切面功能注入**
   - 在不修改组件核心逻辑的情况下，注入额外功能
   - 支持日志记录、性能监控、错误处理等横切面功能
   - 实现关注点分离，保持代码的清洁和模块化

2. **中间状态透出** 
   - 获取组件执行过程中的中间状态
   - 监控执行进度和性能指标
   - 支持调试和问题诊断

3. **核心概念总结**
   - Eino 中的 Component 和 Graph 等实体，在固定的时机 (Callback Timing)，回调用户提供的 function (Callback Handler)，并把自己是谁 (RunInfo)，以及当时发生了什么 (Callback Input & Output) 传出去。


### **核心价值**
- 🔧 **可扩展性**：无侵入式地扩展组件功能
- 📊 **可观测性**：全面监控组件执行状态
- 🐛 **可调试性**：深入了解执行过程
- 🛡️ **可维护性**：分离横切面逻辑

## 📋 **回调机制关键要素**

### **1. 触发实体 (Trigger Entities)**

回调可以在以下三个层级上被触发：

#### **Component 级别**
```
单个组件的执行回调
- ChatModel、Tool、Retriever 等基础组件
- Lambda 自定义组件
- 任何实现了组件接口的实体
```

#### **Graph Node 级别**
```
Graph 中单个节点的执行回调
- Graph 内部节点的执行状态
- 节点间数据流转的监控
- 节点级别的性能分析
```

#### **Graph 级别**
```
整个 Graph 的执行回调
- 整体编排的执行状态
- 全局性能指标
- 整体错误处理
```

### **2. 触发时机 (Trigger Timing)**

回调支持以下五种关键时机：

#### **OnStart**
```go
// 组件开始执行时触发
func (h *MyHandler) OnStart(ctx context.Context, runInfo *callbacks.RunInfo, input interface{}) {
    log.Printf("组件 [%s] 开始执行，输入: %+v", runInfo.Name, input)
    // 记录开始时间、预处理等
}
```

#### **OnEnd**
```go
// 组件执行成功结束时触发
func (h *MyHandler) OnEnd(ctx context.Context, runInfo *callbacks.RunInfo, output interface{}) {
    log.Printf("组件 [%s] 执行成功，输出: %+v", runInfo.Name, output)
    // 记录结果、后处理等
}
```

#### **OnError**
```go
// 组件执行出错时触发
func (h *MyHandler) OnError(ctx context.Context, runInfo *callbacks.RunInfo, err error) {
    log.Printf("组件 [%s] 执行失败: %v", runInfo.Name, err)
    // 错误记录、告警等
}
```

#### **OnStartWithStreamInput**
```go
// 流式输入开始时触发
func (h *MyHandler) OnStartWithStreamInput(ctx context.Context, runInfo *callbacks.RunInfo, input interface{}) {
    log.Printf("组件 [%s] 开始处理流式输入", runInfo.Name)
    // 流式处理的特殊初始化
}
```

#### **OnEndWithStreamOutput**
```go
// 流式输出结束时触发
func (h *MyHandler) OnEndWithStreamOutput(ctx context.Context, runInfo *callbacks.RunInfo, output interface{}) {
    log.Printf("组件 [%s] 流式输出完成", runInfo.Name)
    // 流式处理的清理工作
}
```

### **3. 回调处理器参数**

每个回调方法都接收三类关键参数：

#### **Context**
```go
ctx context.Context
// - 请求上下文信息
// - 超时控制
// - 取消信号
// - 跨组件数据传递
```

#### **RunInfo (元信息)**
```go
type RunInfo struct {
    Name     string              // 组件/节点名称
    Type     string              // 组件类型
    Component components.Component // 组件实例
}
```

#### **Input/Output (业务数据)**
```go
// OnStart 和 OnStartWithStreamInput 接收 input
input interface{}   // 输入数据

// OnEnd 和 OnEndWithStreamOutput 接收 output  
output interface{}  // 输出数据

// OnError 接收 error
err error           // 错误信息

// OnStartWithStreamInput 和 OnEndWithStreamOutput 接收 streamInput/streamOutput
streamInput interface{}
streamOutput interface{}

// Callback Input 和 Callback Output
CallbackInput interface{}
CallbackOutput interface{}

具体到某个组件，有更具体的类型，比如 Chat Model
// CallbackInput is the input for the model callback.
type CallbackInput struct {
   // Messages is the messages to be sent to the model.
   Messages []*schema.Message
   // Tools is the tools to be used in the model.
   Tools []*schema.ToolInfo
   // Config is the config for the model.
   Config *Config
   // Extra is the extra information for the callback.
   Extra map[string]any
}

// CallbackOutput is the output for the model callback.
type CallbackOutput struct {
   // Message is the message generated by the model.
   Message *schema.Message
   // Config is the config for the model.
   Config *Config
   // TokenUsage is the token usage of this request.
   TokenUsage *TokenUsage
   // Extra is the extra information for the callback.
   Extra map[string]any
}
```

#### **返回信息**
```go
并都会返回新的 Context：用于同一个 Handler 的不同触发时机之间传递信息。
```

## 🔧 **回调注入方式**

### **方式一：全局注入**

全局注入对所有组件和编排————都生效，是最广泛的监控方式。

#### **使用方法**
```go
import "github.com/cloudwego/eino/callbacks"

// 创建全局处理器
globalHandler := &MyGlobalHandler{}

// 全局注入
callbacks.AppendGlobalHandlers(globalHandler)

// 之后所有的组件执行都会触发这个处理器
```

#### **典型应用场景**
- 🔍 **全局监控**：系统级别的性能监控
- 📝 **统一日志**：所有组件的统一日志记录
- 📊 **指标收集**：全局指标统计
- 🚨 **全局告警**：系统级别的错误告警

#### **完整示例**
```go
type GlobalMonitorHandler struct {
    metrics *MetricsCollector
    logger  *Logger
}

func (h *GlobalMonitorHandler) OnStart(ctx context.Context, runInfo *callbacks.RunInfo, input interface{}) {
    h.metrics.IncrementCounter("component_start", map[string]string{
        "component": runInfo.Name,
        "type":      runInfo.Type,
    })
    h.logger.Info("Global: Component started", "name", runInfo.Name)
}

func (h *GlobalMonitorHandler) OnEnd(ctx context.Context, runInfo *callbacks.RunInfo, output interface{}) {
    h.metrics.IncrementCounter("component_success", map[string]string{
        "component": runInfo.Name,
        "type":      runInfo.Type,
    })
    h.logger.Info("Global: Component completed", "name", runInfo.Name)
}

func (h *GlobalMonitorHandler) OnError(ctx context.Context, runInfo *callbacks.RunInfo, err error) {
    h.metrics.IncrementCounter("component_error", map[string]string{
        "component": runInfo.Name,
        "type":      runInfo.Type,
        "error":     err.Error(),
    })
    h.logger.Error("Global: Component failed", "name", runInfo.Name, "error", err)
}

// 注册全局处理器
func init() {
    globalHandler := &GlobalMonitorHandler{
        metrics: NewMetricsCollector(),
        logger:  NewLogger(),
    }
    callbacks.AppendGlobalHandlers(globalHandler)
}
```

### **方式二：Graph 内注入**

针对特定的 Graph 或 Node 进行————回调注入，实现细粒度控制。
- 通过 compose.WithCallbacks 在 graph 运行时注入 Handler，这些 Handler 会在 graph 的本次运行整体上生效，包括 Graph 内各 Node 和 Graph 自身（以及各内嵌的 graph）。

- 通过 compose.WithCallbacks(...).DesignateNode(...) 向顶层 Graph 的某个 Node 注入 Handler。当这个 Node 自身是个内嵌的 Graph 时，会注入到这个内嵌 Graph 自身和其内部的各 Node。

- 通过 compose.WithCallbacks(...).DesignateNodeForPath(...) 向内部嵌套的 Graph 的某个 Node 注入 Handler。



#### **使用方法**
```go
// 创建特定的处理器
graphHandler := &MyGraphHandler{}

// Graph 级别注入
graph := compose.NewGraph[InputType, OutputType](
    compose.WithCallbacks(graphHandler),
)

// 或者为特定节点注入
graph.AddNode("specific_node", nodeComponent,
    compose.WithCallbacks(nodeHandler),
)
```

#### **典型应用场景**
- 🎯 **特定业务监控**：针对特定业务流程的监控
- 🔧 **A/B 测试**：特定实验组的数据收集
- 🐛 **问题调试**：特定组件的详细调试
- 📈 **性能优化**：特定热点的性能分析

#### **完整示例**
```go
type BusinessFlowHandler struct {
    businessMetrics *BusinessMetrics
}

func (h *BusinessFlowHandler) OnStart(ctx context.Context, runInfo *callbacks.RunInfo, input interface{}) {
    // 业务特定的开始处理
    if runInfo.Type == "ChatModel" {
        h.businessMetrics.RecordChatStart(runInfo.Name)
    }
}

func (h *BusinessFlowHandler) OnEnd(ctx context.Context, runInfo *callbacks.RunInfo, output interface{}) {
    // 业务特定的结束处理
    if runInfo.Type == "ChatModel" {
        if chatOutput, ok := output.(*ChatModelOutput); ok {
            h.businessMetrics.RecordTokenUsage(chatOutput.TokenCount)
        }
    }
}

// 构建带回调的 Graph
func BuildBusinessGraph() *compose.Graph[BusinessInput, BusinessOutput] {
    businessHandler := &BusinessFlowHandler{
        businessMetrics: NewBusinessMetrics(),
    }
    
    graph := compose.NewGraph[BusinessInput, BusinessOutput](
        compose.WithCallbacks(businessHandler),
    )
    
    // 添加节点...
    return graph
}
```

### **方式三：Graph 外注入**

为单独使用的组件提供回调能力，适用于————组件级别的独立使用场景。

- 不想使用 Graph，但却想使用 Callback，则：

- 通过 InitCallbacks(ctx context.Context, info *RunInfo, handlers ...Handler) 获取一个新的 Context 并注入 Handlers 以及 RunInfo。



#### **使用方法**
```go
// 创建处理器
componentHandler := &MyComponentHandler{}

// 创建 RunInfo
runInfo := &callbacks.RunInfo{
    Name: "my_component",
    Type: "ChatModel",
    ID:   "unique_id",
}

// 初始化回调
ctx = callbacks.InitCallbacks(ctx, runInfo, componentHandler)

// 使用带回调的组件
result, err := component.Invoke(ctx, input)
```

#### **典型应用场景**
- 🧪 **组件测试**：单元测试中的组件监控
- 🔬 **性能测试**：单个组件的性能基准测试
- 🛠️ **工具脚本**：独立工具脚本中的组件使用
- 📋 **原型开发**：快速原型中的简单监控

#### **完整示例**
```go
type ComponentTestHandler struct {
    startTime time.Time
    testName  string
}

func (h *ComponentTestHandler) OnStart(ctx context.Context, runInfo *callbacks.RunInfo, input interface{}) {
    h.startTime = time.Now()
    fmt.Printf("Test [%s]: Component [%s] started\n", h.testName, runInfo.Name)
}

func (h *ComponentTestHandler) OnEnd(ctx context.Context, runInfo *callbacks.RunInfo, output interface{}) {
    duration := time.Since(h.startTime)
    fmt.Printf("Test [%s]: Component [%s] completed in %v\n", h.testName, runInfo.Name, duration)
}

func (h *ComponentTestHandler) OnError(ctx context.Context, runInfo *callbacks.RunInfo, err error) {
    fmt.Printf("Test [%s]: Component [%s] failed: %v\n", h.testName, runInfo.Name, err)
}

// 测试函数示例
func TestChatModelWithCallback(t *testing.T) {
    // 创建测试处理器
    testHandler := &ComponentTestHandler{
        testName: "ChatModel_Basic_Test",
    }
    
    // 创建 RunInfo
    runInfo := &callbacks.RunInfo{
        Name: "test_chat_model",
        Type: "ChatModel",
        ID:   fmt.Sprintf("test_%d", time.Now().UnixNano()),
    }
    
    // 初始化回调上下文
    ctx := context.Background()
    ctx = callbacks.InitCallbacks(ctx, runInfo, testHandler)
    
    // 创建和使用组件
    chatModel := createChatModel()
    result, err := chatModel.Generate(ctx, "Hello, world!")
    
    // 验证结果
    assert.NoError(t, err)
    assert.NotEmpty(t, result)
}
```

## 🎨 **回调处理器设计模式**

### **1. 组合处理器模式**

通过组合多个专门的处理器来实现复杂的回调逻辑。

```go
type CompositeHandler struct {
    handlers []callbacks.Handler
}

func (h *CompositeHandler) OnStart(ctx context.Context, runInfo *callbacks.RunInfo, input interface{}) {
    for _, handler := range h.handlers {
        if startHandler, ok := handler.(interface {
            OnStart(context.Context, *callbacks.RunInfo, interface{})
        }); ok {
            startHandler.OnStart(ctx, runInfo, input)
        }
    }
}

// 使用示例
func CreateProductionHandler() callbacks.Handler {
    return &CompositeHandler{
        handlers: []callbacks.Handler{
            &MetricsHandler{},
            &LoggingHandler{},
            &TracingHandler{},
            &AlertingHandler{},
        },
    }
}
```

### **2. 类型特化处理器模式**

根据组件类型提供不同的处理逻辑。

```go
type TypeSpecificHandler struct {
    chatModelHandler callbacks.Handler
    toolHandler      callbacks.Handler
    retrieverHandler callbacks.Handler
}

func (h *TypeSpecificHandler) OnStart(ctx context.Context, runInfo *callbacks.RunInfo, input interface{}) {
    switch runInfo.Type {
    case "ChatModel":
        if h.chatModelHandler != nil {
            h.chatModelHandler.OnStart(ctx, runInfo, input)
        }
    case "Tool":
        if h.toolHandler != nil {
            h.toolHandler.OnStart(ctx, runInfo, input)
        }
    case "Retriever":
        if h.retrieverHandler != nil {
            h.retrieverHandler.OnStart(ctx, runInfo, input)
        }
    }
}

// 使用 Helper 创建
func CreateTypeSpecificHandler() callbacks.Handler {
    return NewHandlerHelper().
        ChatModel(&ChatModelHandler{}).
        Tool(&ToolHandler{}).
        Retriever(&RetrieverHandler{}).
        Handler()
}
```

### **3. 条件处理器模式**

基于条件来决定是否执行回调逻辑。

```go
type ConditionalHandler struct {
    condition func(*callbacks.RunInfo) bool
    handler   callbacks.Handler
}

func (h *ConditionalHandler) OnStart(ctx context.Context, runInfo *callbacks.RunInfo, input interface{}) {
    if h.condition(runInfo) {
        h.handler.OnStart(ctx, runInfo, input)
    }
}

// 使用示例
func CreateDebugHandler() callbacks.Handler {
    return &ConditionalHandler{
        condition: func(runInfo *callbacks.RunInfo) bool {
            // 只在调试模式下或特定组件上执行
            return os.Getenv("DEBUG") == "true" || runInfo.Name == "debug_target"
        },
        handler: &DetailedLoggingHandler{},
    }
}
```

## 📊 **流式处理回调**

### **流式输入处理**

```go
type StreamInputHandler struct {
    streamMetrics *StreamMetrics
}

func (h *StreamInputHandler) OnStartWithStreamInput(ctx context.Context, runInfo *callbacks.RunInfo, input interface{}) {
    if stream, ok := input.(<-chan Data); ok {
        h.streamMetrics.StartStreamProcessing(runInfo.Name)
        
        // 监控流的处理
        go h.monitorStreamInput(ctx, runInfo.Name, stream)
    }
}

func (h *StreamInputHandler) monitorStreamInput(ctx context.Context, componentName string, stream <-chan Data) {
    count := 0
    for {
        select {
        case data, ok := <-stream:
            if !ok {
                h.streamMetrics.RecordStreamCompleted(componentName, count)
                return
            }
            count++
            h.streamMetrics.RecordStreamItem(componentName, data.Size())
        case <-ctx.Done():
            h.streamMetrics.RecordStreamCanceled(componentName, count)
            return
        }
    }
}
```

### **流式输出处理**

```go
type StreamOutputHandler struct {
    outputCollector *OutputCollector
}

func (h *StreamOutputHandler) OnEndWithStreamOutput(ctx context.Context, runInfo *callbacks.RunInfo, output interface{}) {
    if stream, ok := output.(<-chan Result); ok {
        // 收集流式输出的结果
        go h.collectStreamOutput(ctx, runInfo.Name, stream)
    }
}

func (h *StreamOutputHandler) collectStreamOutput(ctx context.Context, componentName string, stream <-chan Result) {
    defer func() {
        // 确保流资源的正确释放
        if closer, ok := stream.(io.Closer); ok {
            closer.Close()
        }
    }()
    
    for {
        select {
        case result, ok := <-stream:
            if !ok {
                h.outputCollector.MarkStreamComplete(componentName)
                return
            }
            h.outputCollector.CollectResult(componentName, result)
        case <-ctx.Done():
            h.outputCollector.MarkStreamCanceled(componentName)
            return
        }
    }
}
```

## 🚀 **最佳实践指南**

### **1. 回调处理器设计原则**

#### **避免修改 Input/Output**
```go
// ❌ 错误示例：修改输入输出数据
func (h *BadHandler) OnStart(ctx context.Context, runInfo *callbacks.RunInfo, input interface{}) {
    if data, ok := input.(*MyData); ok {
        data.Modified = true // 不要修改输入数据
    }
}

// ✅ 正确示例：只读取不修改
func (h *GoodHandler) OnStart(ctx context.Context, runInfo *callbacks.RunInfo, input interface{}) {
    if data, ok := input.(*MyData); ok {
        h.logger.Info("Processing data", "id", data.ID, "size", data.Size)
    }
}
```

#### **避免处理器间信息传递**
```go
// ❌ 错误示例：在处理器间传递状态
type BadHandler struct {
    sharedState map[string]interface{} // 容易出现竞态条件
}

// ✅ 正确示例：使用 Context 传递请求维度信息
func (h *GoodHandler) OnStart(ctx context.Context, runInfo *callbacks.RunInfo, input interface{}) {
    // 将信息存储到 context 中
    ctx = context.WithValue(ctx, "start_time", time.Now())
    ctx = context.WithValue(ctx, "request_id", generateRequestID())
}

func (h *GoodHandler) OnEnd(ctx context.Context, runInfo *callbacks.RunInfo, output interface{}) {
    // 从 context 中获取信息
    if startTime, ok := ctx.Value("start_time").(time.Time); ok {
        duration := time.Since(startTime)
        h.metrics.RecordDuration(runInfo.Name, duration)
    }
}
```

#### **正确处理流式资源**
```go
// ✅ 正确的流式资源处理
func (h *StreamHandler) OnEndWithStreamOutput(ctx context.Context, runInfo *callbacks.RunInfo, output interface{}) {
    if stream, ok := output.(<-chan Data); ok {
        go func() {
            defer func() {
                // 确保流资源的正确关闭
                if closer, ok := stream.(io.Closer); ok {
                    if err := closer.Close(); err != nil {
                        h.logger.Error("Failed to close stream", "error", err)
                    }
                }
            }()
            
            // 处理流数据...
            for data := range stream {
                h.processStreamData(data)
            }
        }()
    }
}
```

### **2. 性能优化最佳实践**

#### **异步处理非关键操作**
```go
type AsyncHandler struct {
    workQueue chan WorkItem
    workers   int
}

func NewAsyncHandler(workers int) *AsyncHandler {
    h := &AsyncHandler{
        workQueue: make(chan WorkItem, 1000),
        workers:   workers,
    }
    
    // 启动工作协程
    for i := 0; i < workers; i++ {
        go h.worker()
    }
    
    return h
}

func (h *AsyncHandler) OnEnd(ctx context.Context, runInfo *callbacks.RunInfo, output interface{}) {
    // 非阻塞地提交工作项
    select {
    case h.workQueue <- WorkItem{RunInfo: runInfo, Output: output}:
        // 成功提交
    default:
        // 队列满了，可以选择丢弃或记录警告
        h.metrics.IncrementDroppedCallbacks()
    }
}

func (h *AsyncHandler) worker() {
    for item := range h.workQueue {
        h.processWorkItem(item)
    }
}
```

#### **批量处理优化**
```go
type BatchedHandler struct {
    batchSize     int
    flushInterval time.Duration
    buffer        []CallbackEvent
    ticker        *time.Ticker
    mu            sync.Mutex
}

func (h *BatchedHandler) OnStart(ctx context.Context, runInfo *callbacks.RunInfo, input interface{}) {
    event := CallbackEvent{
        Type:    "start",
        RunInfo: runInfo,
        Data:    input,
        Time:    time.Now(),
    }
    
    h.mu.Lock()
    h.buffer = append(h.buffer, event)
    shouldFlush := len(h.buffer) >= h.batchSize
    h.mu.Unlock()
    
    if shouldFlush {
        h.flush()
    }
}

func (h *BatchedHandler) flush() {
    h.mu.Lock()
    if len(h.buffer) == 0 {
        h.mu.Unlock()
        return
    }
    batch := make([]CallbackEvent, len(h.buffer))
    copy(batch, h.buffer)
    h.buffer = h.buffer[:0]
    h.mu.Unlock()
    
    // 批量处理
    h.processBatch(batch)
}
```

### **3. 错误处理最佳实践**

#### **优雅的错误恢复**

```go
type ResilientHandler struct {
    logger Logger
}

func (h *ResilientHandler) OnStart(ctx context.Context, runInfo *callbacks.RunInfo, input interface{}) {
    defer func() {
        if r := recover(); r != nil {
            h.logger.Error("Callback panic recovered", 
                "component", runInfo.Name,

                "stack", string(debug.Stack()))
        }
    }()
    
    // 具体的回调逻辑

}

func (h *ResilientHandler) doCallbackWork(ctx context.Context, runInfo *callbacks.RunInfo, input interface{}) {
    // 可能出现 panic 的代码

}
```

#### **超时控制**
```go
type TimeoutHandler struct {
    timeout time.Duration
}

func (h *TimeoutHandler) OnStart(ctx context.Context, runInfo *callbacks.RunInfo, input interface{}) {
    // 为回调处理设置超时
    callbackCtx, cancel := context.WithTimeout(ctx, h.timeout)
    defer cancel()
    
    done := make(chan struct{})
    go func() {
        defer close(done)
        h.processCallback(callbackCtx, runInfo, input)
    }()
    
    select {
    case <-done:
        // 正常完成
    case <-callbackCtx.Done():
        h.logger.Warn("Callback timeout", 
            "component", runInfo.Name,
            "timeout", h.timeout)
    }
}
```

```go
type PerformanceDiagnosticHandler struct {
    profiler         *Profiler
    performanceDB    *PerformanceDatabase
    thresholds       map[string]time.Duration
}

func (h *PerformanceDiagnosticHandler) OnStart(ctx context.Context, runInfo *callbacks.RunInfo, input interface{}) {
    // 开始性能分析
    profile := h.profiler.StartProfiling(runInfo.Name)
    ctx = context.WithValue(ctx, "profile", profile)
    
    // 记录输入大小等性能相关信息
    inputSize := h.calculateInputSize(input)
    ctx = context.WithValue(ctx, "input_size", inputSize)
    ctx = context.WithValue(ctx, "start_time", time.Now())
}

func (h *PerformanceDiagnosticHandler) OnEnd(ctx context.Context, runInfo *callbacks.RunInfo, output interface{}) {
    startTime := ctx.Value("start_time").(time.Time)
    duration := time.Since(startTime)
    inputSize := ctx.Value("input_size").(int64)
    
    if profile, ok := ctx.Value("profile").(*Profile); ok {
        h.profiler.StopProfiling(profile)
    }
    
    // 记录性能数据
    perfData := &PerformanceData{
        Component:    runInfo.Name,
        Duration:     duration,
        InputSize:    inputSize,
        OutputSize:   h.calculateOutputSize(output),
        MemoryUsage:  h.getCurrentMemoryUsage(),
        CPUUsage:     h.getCurrentCPUUsage(),
        Timestamp:    time.Now(),
    }
    
    h.performanceDB.Store(perfData)
    
    // 检查是否超过阈值
    if threshold, exists := h.thresholds[runInfo.Name]; exists && duration > threshold {
        h.handleSlowExecution(runInfo.Name, duration, threshold, perfData)
    }
}

func (h *PerformanceDiagnosticHandler) handleSlowExecution(component string, actual, threshold time.Duration, perfData *PerformanceData) {
    // 分析慢执行的原因
    analysis := h.analyzeSlowExecution(perfData)
    
    // 记录详细的诊断信息
    h.logger.Warn("Slow execution detected",
        "component", component,
        "actual", actual,
        "threshold", threshold,
        "analysis", analysis,
    )
    
    // 可以触发自动优化建议
    if suggestions := h.generateOptimizationSuggestions(analysis); len(suggestions) > 0 {
        h.logger.Info("Optimization suggestions", "suggestions", suggestions)
    }
}
```

```go
type DebugHandler struct {

func NewDebugHandler(level int, writer io.Writer) *DebugHandler {
    return &DebugHandler{
        debugLevel:   level,
        outputWriter: writer,
        enableTrace:  level >= 2,
    }
}

func (h *DebugHandler) OnStart(ctx context.Context, runInfo *callbacks.RunInfo, input interface{}) {
    if h.debugLevel >= 1 {
        fmt.Fprintf(h.outputWriter, "[DEBUG] START: %s (%s)\n", runInfo.Name, runInfo.Type)
        if h.debugLevel >= 2 {
            fmt.Fprintf(h.outputWriter, "  Input: %+v\n", input)
        }
        if h.enableTrace {
            fmt.Fprintf(h.outputWriter, "  Stack: %s\n", h.getCallStack())
        }
    }
}

func (h *DebugHandler) OnEnd(ctx context.Context, runInfo *callbacks.RunInfo, output interface{}) {
    if h.debugLevel >= 1 {
        fmt.Fprintf(h.outputWriter, "[DEBUG] END: %s\n", runInfo.Name)
        if h.debugLevel >= 2 {
            fmt.Fprintf(h.outputWriter, "  Output: %+v\n", output)
        }
    }
}

func (h *DebugHandler) getCallStack() string {
    buf := make([]byte, 4096)
    n := runtime.Stack(buf, false)
    return string(buf[:n])
}
```

```go
    }

    h.expected[name] = expectedOutput
}

func (h *TestAssertionHandler) OnEnd(ctx context.Context, runInfo *callbacks.RunInfo, output interface{}) {
    h.actual[runInfo.Name] = output
    
    if expected, exists := h.expected[runInfo.Name]; exists {
        assert.Equal(h.t, expected, output, 
            "Component %s output mismatch", runInfo.Name)
    }
}

func (h *TestAssertionHandler) Verify() {
    for expectedName := range h.expected {
        if _, exists := h.actual[expectedName]; !exists {
            h.t.Errorf("Expected component %s was not executed", expectedName)
        }
    }
}
```

## 📈 **总结与发展方向**

### **回调机制的核心价值**

1. **横切面关注点分离**：将监控、日志、性能分析等横切面功能从业务逻辑中分离
2. **可观测性增强**：提供全面的组件执行状态监控和调试能力  
3. **扩展性和灵活性**：支持多种注入方式和自定义处理逻辑
4. **企业级特性支持**：满足生产环境的监控、告警、诊断需求

### **设计原则总结**

- 🔒 **非侵入性**：不影响组件的核心功能和性能
- 🎯 **职责单一**：每个处理器专注于特定的横切面功能
- ⚡ **高性能**：异步处理、批量优化、超时控制
- 🛡️ **容错性**：优雅处理错误，不影响主流程

### **未来发展方向**

- 🚀 **自动化优化**：基于回调数据的自动性能优化建议
- 🤖 **智能告警**：基于机器学习的智能告警和异常检测
- 📊 **可视化支持**：图形化的执行流程监控和分析
- 🔗 **生态集成**：与更多监控、APM、诊断工具的深度集成

Eino 的回调机制为 AI 应用提供了企业级的可观测性和扩展性支持，是构建生产级 AI 系统的重要基础设施。
